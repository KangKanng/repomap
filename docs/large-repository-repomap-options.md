# 超大仓库的 RepoMap 上下文方案

完整索引可以放在仓库外的本地缓存中；进入每次模型请求的表示需要符合端点的上下文容量。保留原样完整文本且容量不足时，需要更大的窗口；改变表示格式、按范围或相关性选取、分层按需读取，是不同的处理方式。

## Lucene 的本地格式压缩实测

使用既有实验实际注入的 Lucene 地图进行文本转换，不调用模型、不重新生成索引。原始地图包含 6,285 个路径和 94,251 行签名片段。计数统一用 `cl100k_base`，下表包含各变体的标签和格式说明。

| 表示 | tokens | 相对原图减少 | 信息变化 |
| --- | ---: | ---: | --- |
| 原始完整地图 | 1,537,102 | — | 原格式 |
| 全部路径与签名，保留缩进 | 987,398 | 35.76% | 去掉行号、空白分隔与省略标记；全部已提取签名文本和原顺序保留 |
| 全部路径与签名，去掉缩进 | 877,475 | 42.91% | 另去掉缩进及行尾空白，类型层级的可读性可能下降 |
| 全部文件路径 | 124,882 | 91.88% | 不保留签名，不等价于完整符号地图 |

这些是本地计数，尚未通过模型请求验证。服务端之前拒绝请求时报告窗口为 1,048,576 tokens；不同表示的服务端分词结果不能直接按原图的比例推算。

保留缩进的紧凑版在本地窗口数字下仅余 61,178 tokens；去缩进版本余 171,101 tokens。它们还需要容纳任务、系统提示、工具定义、后续历史与生成空间。不能将“初始文本估算小于上限”视为整个任务不会超限，也不能直接据此声称搜索效果保持不变。

删除格式并非原文无损压缩：行号和省略标记是定位信息。这里保留的是所有已提取路径/签名，而不是保留原地图的所有字节或元数据。去缩进还可能损失阅读结构，因此应作为单独实验条件评估。

## 可实施的几条路线

| 路线 | 能否保留所有签名在同一请求 | 适用范围与代价 |
| --- | --- | --- |
| 紧凑完整地图 | 视压缩后体积与实际端点窗口而定 | 改动较小，适合先单独验证 Lucene；移除部分定位/排版信息 |
| 更大上下文端点 | 端点输入和总上下文容量足够时可以 | 需要核对实际服务限制，保留历史及输出余量；还需评估费用与长上下文效果 |
| 任务相关预算地图 | 只保留选择出的部分签名 | 对全仓库索引排序，输出预算内的定义；当前 `mode=budget` 已实现固定预算选取 |
| 按模块限定范围 | 模块内完整，仓库整体不完整 | 任务可以定位到模块时实用；跨模块依赖需要额外纳入 |
| 分层地图与按需展开 | 完整索引在本地，单次请求只包含需要部分 | 初始提供模块概览，随后按模块/路径/符号读取详细地图；适合索引持续超过窗口的大仓库 |

Aider 官方对大型仓库采取的是在完整索引上进行图排名，再选择符合 token 预算的相关部分，并会根据对话状态调整地图大小；它不保证每次将全部符号放入上下文。参考 [官方说明](https://aider.chat/docs/repomap.html)。这与本文的紧凑完整地图是不同方案。

## 对当前 mini-swe-agent 适配的建议

第一步可以增加单独的 `compact-full-once` 条件：保留当前任务、镜像、模型、扫描范围、全部已提取路径/签名与单次注入策略，仅改变渲染格式。先用保留缩进的表示验证容量、目标定位成本、搜索次数和官方成功率，再决定是否需要进一步去缩进或改变索引结构。它目前只是已导出的表示样例，尚未接入运行配置，也没有新跑推理。

对更大的仓库，可以增加宿主机完整索引和模块化查询工具：初始只给全局模块概览；Agent 按路径、模块或符号请求详细地图，工具返回有预算上限的片段，并注明省略内容。模块检索结果与具体源码读取仍按需求进入历史；当前版本没有实现这一工具或相应的历史管理策略。

新增地图检索应计入搜索次数和定位成本，避免因为把 Bash 搜索换成另一种工具名而产生虚假的搜索下降。实验仍需检查 Resolved Rate 约束。

查询前应按端点定义校验实际可用窗口：

```text
地图预算 ≤ 可用上下文 − 系统/任务/工具定义 − 已有历史 − 输出预留 − 计数误差余量
```

当前适配没有实现全请求窗口预检。仅检查地图 token 数不够；本地 `cl100k_base` 与模型端分词计数的差异也需要处理。预检失败时应明确报错或按预先登记的策略降级，不能静默把完整地图实验改成预算地图。

将同一张地图拆成多条消息，仍会累计占用同一请求的窗口。Prompt cache 也不把已缓存内容从上下文中删除。gzip 可以用于本地存储或传输，解压后交给模型的文本仍占上下文；把压缩字节编码成文本发给普通聊天接口不能当作可可靠读取的代码索引。
