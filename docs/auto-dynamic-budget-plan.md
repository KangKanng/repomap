# Auto 刷新与动态地图预算实施计划

状态：auto 与动态预算仍为设计方案，尚未实现或启动相应模型实验。
当前已另行实现固定预算的 `refresh=once`，每个任务只生成并注入一次地图；它不属于 auto 或动态预算。

## 可行性与源码依据

当前实现已有源码快照指纹、Tree-sitter 解析缓存、按 token 裁剪的渲染器，以及模型查询前的消息注入入口，可以在这些接口上增加刷新策略与预算策略，无需把 Aider 整套 Agent 引入 mini。

已核对的上游源码：

- [aider/repomap.py：get_ranked_tags_map](https://github.com/Aider-AI/aider/blob/main/aider/repomap.py#L529)：`auto` 的缓存键包含文件集合、预算、提及的文件和标识符；上次地图构建超过 1 秒且键命中时复用缓存，否则重新构建。
- [aider/repomap.py：get_repo_map](https://github.com/Aider-AI/aider/blob/main/aider/repomap.py#L95)：没有聊天文件时放大地图预算，并按模型上下文窗口预留空间。
- [aider/args.py：Repomap settings](https://github.com/Aider-AI/aider/blob/main/aider/args.py#L239)：CLI 提供 `auto/always/files/manual`，无聊天文件倍率默认 2。底层 `RepoMap` 构造器的倍率默认 8，不应混淆两种入口。
- [aider/coders/base_coder.py：get_repo_map](https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py#L657)：组装聊天文件集合和提及的文件、符号。

实施时记录所参考的上游 commit SHA，避免后续 main 分支变化导致语义不明确。

这里有两个独立目标：本地地图缓存减少扫描、排序或渲染开销；模型服务端提示词缓存减少计费输入。前者不会自动保证后者命中。`auto` 在构建很快或语义信号变化时仍可能频繁产生新地图，不能预先承诺费用降低。

## 1. 配置与兼容

拟在 `settings.py` 增加配置：

```yaml
# 设计示例，当前版本尚不支持这些新增字段。
agent:
  repomap:
    refresh: auto
    auto_refresh_threshold_seconds: 1.0
    budget_mode: dynamic
    map_tokens: 1024
    map_multiplier_no_files: 2
    map_tokens_max: 2048
    context_window_tokens: null
    reserve_tokens: 4096
```

- `refresh` 支持 `interval/always/auto/files/manual`；默认保留 `interval`，继续使用已有 `refresh_interval`，以便复现原实验。
- `budget_mode` 支持 `fixed/dynamic`；默认保留 `fixed`。新功能通过单独 overlay 启用。
- `map_tokens` 是基础预算；`map_tokens_max` 是适配版的额外硬上限。首次验证使用 1024 基础预算、2 倍探索倍率、2048 硬上限。
- `context_window_tokens` 优先显式配置，其次使用可信模型元数据；动态模式无法确认模型上限时，在首个模型请求前明确报配置错误，不猜测上限。
- `map_tokens=0` 继续完全跳过收集、地图构建和注入；同一 Agent 再次 `run()` 时清空任务相关缓存状态。

## 2. Auto 刷新与失效条件

在现有 `agent.py` 查询钩子与新增 `policy.py` 之间划分职责：前者处理消息与环境，后者决定复用、重建和预算。

一次查询的处理顺序：

1. 计算基础请求的上下文占用，得出当前可用地图预算；基础预算为 0 时直接跳过。
2. 读取仓库快照。现有收集器在指纹未变化时已只返回 `unchanged`，但仍需在容器中检查文件元数据，不能声称完全没有扫描开销。
3. 构造与排序输入一致的键：仓库/任务、快照指纹、活动文件、相关文件/符号信号、实际预算和影响排序的设置。
4. 按策略决定是否调用已有 `RepoMap.build()`；继续复用已有的 AST 缓存。
5. 文本相同则保留地图消息；文本变化时只替换唯一地图消息。地图正文不加入计时、轮数或统计字段。

策略定义：

| 策略 | 计划行为 |
| --- | --- |
| `interval` | 保留已有按调用次数刷新的行为 |
| `always` | 每次重建地图，仍允许底层 AST 缓存 |
| `auto` | 对齐上游耗时阈值逻辑；超过阈值且完整键命中时复用，否则重建 |
| `files` | 忽略近期提及变化；文件集合、源码指纹或预算变化时重建 |
| `manual` | 在当前任务内保持地图，首次查询和显式强制刷新时构建 |

适配版的 `auto/files` 键额外包含快照指纹，避免相同路径的源码已修改而缓存仍保留旧签名/行号。这是相对上游缓存键的明确差异。`manual` 主动保留旧地图，需要在文档说明这一语义。

键中的上下文使用排序实际消费的文件/符号信号，不直接使用不断变化的整段工具日志；必须保证键相同意味着排序输入等价。缓存采用有界 LRU，防止长任务持续累积地图。

## 3. mini 的活动文件信号

mini-swe-agent 使用任意 Bash 动作，没有 Aider `/add` 维护的原生 `chat_files`。不能简单把“聊天文件永远为空”作为两倍预算的理由，也不能把日志中出现一个路径等同于文件正文已进入上下文。

先建立 `active_files` 适配接口：

- 支持显式提供活动文件，便于确定性测试与外部工具接入。
- 针对已成功执行且可明确解析的读文件命令，记录仓库内的实际路径；修改文件可通过工作区差异和快照变化确认。
- 任意脚本、复杂管道或不明确的命令不强行推断，保留 `unknown` 状态。状态未知时使用基础预算，并记录原因。
- `active_files` 用于决定探索/聚焦预算；近期提及的文件和符号单独用于排序，不混为一个信号。

因此，这部分属于 mini 的适配规则，不宣称与 Aider 原生聊天文件语义完全等价。第一版不把补丁 gold 文件或官方隐藏测试信息用于推理。

## 4. 动态预算

候选预算：明确没有活动文件时为 `基础预算 × 无文件倍率`，存在活动文件或状态未知时为基础预算。最终预算再受硬上限和剩余上下文约束。

```text
剩余输入空间 = 模型可用输入上限 - 不含地图的完整请求 token - 安全预留
实际地图预算 = max(0, min(候选预算, 地图硬上限, 剩余输入空间))
```

模型可用输入上限同时考虑服务端最大输入限制，以及总上下文扣除计划输出空间后的限制。完整请求包括系统提示词、历史消息、工具结果、工具定义、格式开销；地图的包装标签计入地图预算。

优先使用匹配模型的 token 计数；估算时记录编码和估算方式并保留余量。预算比较使用统一计数口径；若为兼容性保留 `cl100k_base` 地图硬上限，还须用模型计数复核注入后的完整请求，必要时继续裁剪，不能直接混用两种 token 单位。不得把 `cl100k_base` 的地图计数称为所有模型都精确的请求计数。地图可以缩减至空；不含地图的请求本身已超限时明确报告，不通过静默丢弃任务或历史消息解决。

预算只随活动文件状态或空间阈值切换，预留余量减少反复扩缩；需要立即缩小才能满足空间限制时不能延迟。地图 token 预算与 `max_files/max_file_bytes/max_total_bytes` 是独立限制，扩大输出预算不会自动解决 Django、Lucene 的扫描截断。

## 5. 指标与改动位置

| 文件 | 计划改动 |
| --- | --- |
| `settings.py` | 新字段、取值范围、模式兼容规则 |
| 新增 `policy.py` | 刷新决策、缓存键、动态预算计算 |
| `agent.py` | 状态复位、活动文件信号、单一消息更新、调用策略层 |
| `source.py` | 暴露快照是否变化、候选文件元数据，继续复用收集器 |
| `repomap.py` | 复用已有解析、排序和裁剪；仅在决策要求时构建 |
| `config/` | 新增 auto、auto+dynamic overlay，保留原配置 |
| `scripts/` | 保存有效策略、实际预算和新增指标；复用原推理/评测入口 |
| `tests/` | 验证缓存失效、预算边界与 Agent 集成 |
| `docs/` | 参数、使用方式、上游与适配语义差异 |

每轮另存以下数据到轨迹 `info` 或独立指标文件，不进入模型可见的地图正文：

- `collection_seconds`、`build_seconds`、是否复用、刷新原因。
- 基础/候选/实际预算、实际地图 tokens、预算改变原因。
- 地图内容哈希、是否与上一轮相同、活动文件状态。
- 快照指纹变化、扫描截断原因、token 计数方式。
- 模型请求总耗时；与地图阶段分别计时，覆盖正常返回和格式错误。

这能区分本地地图缓存与服务端 `cached_tokens`，也能补足上一轮统计中无法独立测量地图耗时的问题。费用仍以服务端 `usage.cost` 为准。

## 6. 验证与实验

先完成不调用真实模型的验证：

1. 用可控时钟验证 `auto` 超过/未超过 1 秒的分支、命中和失效。
2. 验证源码新增、修改、删除、任务切换、预算切换不会误用旧地图。
3. 验证 `fixed`、探索放大、聚焦回落、状态未知、上下文不足、模型元数据缺失和 `map_tokens=0`。
4. 验证文本/Chat Completions/Responses 三类消息路径中只存在一份地图，工具调用配对和费用记录正确。
5. 在已有 Gson、Tokio 修复镜像中执行假模型断网集成验证。

随后安排受控模型实验，区分两项功能各自的效果：

| 组 | 刷新 | 预算 |
| --- | --- | --- |
| plain | 关闭地图 | 0 |
| static | 与原实验相同的每轮刷新 | 固定 1024 |
| auto | auto | 固定 1024 |
| auto+dynamic | auto | 基础 1024、上限 2048 |

四组使用相同的 20 条任务、修复镜像、模型、提示词、限制和 `network=none`；按实例交错执行或轮换顺序，记录顺序与缓存状态。扫描上限在四组中保持同一设置。评测继续使用原官方测试。

主要观察解决率、实际费用、输入/输出/缓存 tokens、模型调用数；新增观察地图重建次数、内容变化次数、构建耗时、预算轨迹及扫描截断。历史 17/20 与 16/20 只作为参考；单次 20 条实验不能确认一般性提升。
