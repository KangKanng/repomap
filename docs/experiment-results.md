| 容器网络 | none | none | none |

模型请求配置名为 `openrouter/deepseek/deepseek-v4.1-flash-1017`，服务端响应模型名为 `deepseek/deepseek-v4.1-flash-1017`。地图预算包含标签和说明，按 `cl100k_base` 计数，是上限而非必须填满；与模型实际计费 token 口径分别记录。

模型推理主要限制为每条任务 250 步、1200 秒、费用停止阈值 $3，并发 2；官方判题单路，超时 900 秒。本轮 once 另使用 1380 秒进程级时限。预算实验中 Redis 挂起后也加装了进程时限，原始尝试完整保留。

统计定义：

- **官方通过**：官方 harness 标记 `resolved=true`，满足该任务指定的修复及回归判分项；不表示整个仓库所有测试均通过。
- **搜索子命令**：Bash AST 中显式请求的文件定位、文本搜索和日志过滤命令。单条 Bash 动作可包含多个子命令。
- **搜索请求**：包含至少一个搜索子命令的 Bash 动作，一条动作只计一次。
- **未计入搜索**：普通读文件、`ls`、自定义脚本内部搜索、地图收集器扫描。命令请求数不保证每个条件分支都成功执行。
- **缓存输入占比**：服务端 cached prompt tokens / prompt tokens，按 token 加权；不是 API 请求缓存命中率。
- **最终费用**：每个任务最终有效轨迹的费用；**全部已返回费用**：另加失败尝试已返回的费用。未返回请求费用保持未知。

## 8. 已有证据能解释什么

- **地图相关性存在噪声**：Bat 的重建首轮 1024 地图包含压缩 jQuery benchmark 样本，未列出目标 `src/assets.rs`。这是离线确定性重建，不能冒充当时抓取的请求；历史轨迹没有保存每一轮地图。
- **定位正确仍可能修错**：SymPy 的 2048 方案修改了正确文件，却对维度不同的点直接抛异常；任务要求补齐维度，因此官方测试失败。fmt 的 1024 方案引入零填充回归，2048/4096 保留必要行为后通过。
- **搜索量包含验证过程**：Tokio 4096 修改 5 个文件，包含编译诊断过滤和类型追踪；plain 修改 1 个文件。搜索次数不只衡量首次找文件的难度。
- **适配与方法尚未分离验证**：当前采用自实现符号提取、排序和消息接入；按符号名连边也存在于 Aider 原版，不能将这一点独自归因于适配错误。尚无原版生成器在同一框架内的对照结果。

详细证据：[搜索结果原因分析](../benchmarks/results/budget-sweep-20261102T035731Z/search-result-analysis.md)。这些案例支持检查地图质量和修复路径，但不能单独确定整体结果的因果来源。

## 9. 费用、失败尝试与局限

已完成两轮实验的 **2,632 条收费响应**均核对 `extra.cost == usage.cost`。上述 122 次尝试已返回费用合计 **$6.52352059976**；不含本轮 once 的运行中费用，也不等于整个项目所有早期试运行的总账单。

两次正式实验补跑均保留原始尝试：

1. 早期 RepoMap 的 Ripgrep 启动失败后修正配置重跑。20 条最终费用 $1.53407461556，包含失败尝试的已返回费用 $1.80645811036。
2. 预算实验 Redis plain 的模型请求挂起，保留原始轨迹和已返回费用 $0.019981842，再以相同设置补跑。其最后一条未返回请求费用未知，不能计为零。

每个仓库只有一个任务，每条件只有一次最终有效运行；不能从 16/20 与 17/20 的差异推导稳定提升。历史两轮的镜像、扫描与缓存不同；缓存差异伴随费用差异，不能用它解释搜索行为的因果变化。早期试运行、确定性模型验证和失败启动在目录分类中单列，不混入上面的完整模型结果。
